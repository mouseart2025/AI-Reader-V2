# Q0 质量数据人工核对工具

为 Q0 质量基线 **1100 条人工核对** 设计的极简本地页面：无脑键盘刷判。

## 启动

```bash
cd scripts/qa-review
./run.sh            # 或 python3 serve.py
# 浏览器打开 http://localhost:8273
```

数据目录默认指向 `~/Baiduyun/AISoul/ai-reader-internal/analysis/quality-baseline-2026-08`。
可用环境变量覆盖：

```bash
QA_DATA_DIR=/path/to/data QA_PORT=9000 python3 serve.py
```

## 判定操作

| 按键 | M3（父子方向） | M2（地点真伪） |
|------|---------------|---------------|
| `1` | 正确 | 真地点 |
| `2` | 错误 | 非地点 |
| `3` | 不确定 | 跳过（不标记） |
| `←` / `Backspace` | 撤销上一条 | 撤销上一条 |
| `J / K` | 上下浏览（不标记） | 上下浏览 |

按 `1`/`2`/`3` 即写即进，无需回车。`#f-status` 可切「只看未标 / 需复核 / 全部 / 已标」。

## 判定标准速查

- **M2 地点真伪**：专有地名=真（任意粒度）；泛称 / 人名 / 幻觉 = 假。
- **M3 父子方向**：correct=「父≥子」方向对；wrong=方向错；uncertain=判断不了。

## 数据安全（冻结 DB 铁律）

- 每次写回自动在原 JSON 旁生成 `.bak` 备份。
- 建议先用 `QA_DATA_DIR` 指向 scratch 副本试跑，确认无误再对真实目录核对。

## AI 预填（证据版 + 双模型交叉）

页面顶栏 `[AI 预填]` 一次调用 **DeepSeek + Qwen 双模型**（key 分别读 `backend/.env` 的
`DEEPSEEK_API_KEY`/`LLM_API_KEY` 与 `DASHSCOPE_API_KEY`），为当前小说待核对项生成预填与置信：

- **DeepSeek**：覆盖 m3+m2 全部项，存 `.prefill-<slug>.json`（**不覆盖人工判定**）。
- **Qwen**（百炼 `qwen3-235b-a22b-instruct-2507`）：仅覆盖 m2 项（m3 父子方向只有 DS），
  存 `.prefill-qwen-<slug>.json`。某模型 key 缺失会自动跳过并在完成提示里注明。

**M2 预填带原文证据**：预填时从冻结 DB（只读副本）按 `±120 字` 窗口截取该名称首次出现的
原文片段（格式 `第N回: …片段…`，找不到则 `(原文未找到)`），连同严格判定标准一起发给模型。
依据 2026-08 对照实验（代码在 `experiments/`）：无证据预填与人工一致率仅 **59%**（且 AI 高置信
是反向指标），带证据 + 严格标准后升至 **84%**。

卡片上的显示：

- M2 卡紧凑显示两模型倾向，如 `DS:假·高 QW:假·高`；M3 卡只显示 DS。
- **双模型状态徽标**（仅 M2 且两侧都有预填）：两侧都 false → 绿底**双否**；都 true →
  灰底**双真**；不一致 → 橙底**分歧**。

**批量确认双否**：顶栏 `[批量确认双否]`（当前小说有 QW 预填时可用）。点击并确认后，对所有
「双否且尚未人工判定」的 M2 项逐条写回 `false`（非地点；m2_cal 写 `is_valid`），已有人工判定
的项绝不覆盖，完成后报告成功/失败条数。依据：双模型交叉实验中一致判假的 71 条**准确率 100%**
（一致判真只有约 70%，故「双真」仍需人工复核）。

- **高置信**：绿底。通常可直接照 1/2/3 快速确认，但仍需你按键。
- **低/中置信**：黄底 + 卡片高亮描边，`#f-status=需复核` 筛选优先处理。
- 「双否/双真/分歧」徽标仅参考；是否采用由你按键决定。

> 预填可靠性（2026-08 修复）：曾出现"只填充部分（如 10 条）"的 bug——因 LLM 返回
> `id` 为从 0 起的序号，而程序错按 `c0/q0` 前缀匹配导致 m2 全丢。已修复为**按序号逐条归位**
> + DeepSeek 批 25 / Qwen 批 15（防截断）+ 失败重试。现可一次填满全集。
> 若仍发现只填部分，重跑「AI 预填」即可覆盖（不覆盖已人工判定）。

清除某部预填：`POST /api/prefill-clear` body `{"slug":"xiyouji"}`（仅清 DeepSeek 侧）。

## M3 / M2 问题标记

核对卡按类型显示**独立勾选框**（方向判定 `human_verdict` / `is_valid` 之外，写回 `issue_type`，`|` 分隔多 token）：

### M3 方向对（三个标记）
1. **复合全称 / 缺中间层**（`missing_intermediate`）— `西天 → 西天大雷音寺`，真实谱系 `西天 → 灵山 → 大雷音寺`，缺"灵山"。
2. **泛称 / 非实体节点**（`entity_issue`）— `高山 → 东城`，父或子为纯泛称/方位概念，非独立地理实体。
3. **异名 / 拼写变体**（`alias_variant`）— `南赡部洲 → 南瞻部洲`，同一实体异写/错别字/简称被拆成两节点。

### M2 地名真伪（一个标记）
4. **通名 / 待挂父级**（`generic_attachment`）— `大雄宝殿`，纯泛称建筑/场所名，在原文真实存在但单拎非专名，应挂所属父级（区别于纯幻觉假）。

全部有**保守预筛建议**自动预勾（`issue_suggested`/`entity_suggested`/`alias_suggested`/`generic_suggested`），
人工可取消。底部状态条分别计数；筛选分别可选。用途：核对后按 `issue_type` 统计，量化各类建模
问题规模，为 Phase 1（D1 信号扩展）管线修复提供数据。

## 最近已判（快速返回修订）

底部「已判」横条保留**最近 30 条已核对项**（载入小说时自动用已持久化的已判项填充，会话中
新判定实时加入），每条显示简称 + 判定色点 + 问题标记符号（缺=复合全称 / 泛=泛称 / 异=异名 /
通=通名）。点击即跳回该条修订，改判后自动更新；`←` 撤销同步从列表移除；`清空` 重置列表；
切小说重新填充。适用"几秒后觉得刚才可能标错了"返回改判的场景，不打断主刷判流程。

> 若页面未更新：浏览器强刷（Cmd+Shift+R / Ctrl+F5）以获取最新 app.js（已加版本号避免缓存）。

## 批量模式（一屏 5 张）

工具栏「逐卡 / 批量×5」切换。**批量模式**一屏显示 5 个待核对项：

- **焦点卡**（粗蓝框）持有 1/2/3 判定权；`←/→` 或 `Tab` 移动焦点。
- 每卡右下角有**独立迷你判定按钮**（也可鼠标点），判定后卡原地打勾减淡。
- **M2 卡**：显示「通名/待挂父级」迷你勾选框；第 3 个按钮为「跳」（跳过=标记已处理，不落盘判定）。
- **M3 卡**：第 3 个按钮为「不」（uncertain）。
- 每卡显示 **AI 预填倾向**（高/低置信）+ 问题标记符号。
- **本批 5 张全判定（或跳过）后自动换下一批**；也可点「下一批」手动前跳。
- 底部「已判」横条与两模式共享，随时点回修订。
- 逐卡模式保留原「大焦点无脑刷判」流程，两模式切换不丢进度。

## 预填浏览模式

工具栏「预填浏览」：一字列出一部小说的**全部 AI 预填结果**，方便快速判断 AI 靠不靠谱。

每行：`地名(或父→子) ` `DS判定+置信 ` `QW判定+置信 ` `双模型徽标 ` `人工判定 ` `状态`。
- 状态：`✓ 一致`（AI=人工）/ `✗ 不一致` / `未判`（人工还没判）。
- 双模型徽标（仅 M2）：绿`双否` / 灰`双真` / 橙`分歧`；汇总另起一行显示 `双否 N · 双真 M · 分歧 K`。
- 顶部 `#pf-status` 筛选：全部 / 仅高置信 / 仅低中 / 仅一致 / 仅不一致 / 仅双否 / 仅分歧。
- 顶部显示汇总：`共 N 条预填 · 已判 X · 一致 Y · 不一致 Z`。
- 每行名称旁显示**问题标记**：`通`=通名/待挂父级、`缺`=复合全称、`泛`=泛称/非实体、`异`=异名
  （来自规则预筛，非 AI 判定）。
- 点击某行跳回逐卡模式定位，可直接复核/改判。
